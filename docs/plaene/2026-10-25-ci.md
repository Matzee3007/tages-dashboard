# Plan: CI mit GitHub Actions

**Ziel:** GitHub prüft jeden Pull Request und jeden Push auf `main` mit denselben Befehlen wie lokal und baut die
App.

**Vorgehen:** Workflow nach dem Muster von musik-app (`projects/musik-app/.github/workflows/ci.yml`), die
Node-Version kommt aus `engines` in `package.json`. Den Beweis, dass die CI Fehler findet, liefert eine absichtlich
falsch formatierte Probedatei: erst rot, nach dem Löschen grün.

**Technik:** GitHub Actions (`actions/checkout@v7`, `actions/setup-node@v7`), npm-Skripte aus `package.json`, `gh`.

**Anforderung:** [[projects/tages-dashboard/docs/Projektvision|Projektvision]] Phase 0 und
[[projects/tages-dashboard/docs/Nächste Session|Nächste Session]] („evtl. CI“), Entscheidung A vom 2026-10-25.

## Feste Vorgaben

- Branch `ci/github-actions`, ein PR für Plan, Workflow und Doku.
- Node 24 wie lokal (`node -v` → v24.22.0): `"engines": { "node": "24.x" }`.
- Die CI ruft nur npm-Skripte auf (`npm ci`, `npm run check`, `npm run build`), keine eigenen Befehle.
- Auslöser: `pull_request` und `push` auf `main`.
- Gemergt wird erst, wenn `gh pr checks <nr>` grün meldet (GitHub Free hat für private Repos keinen Branch-Schutz).
- Commit-Nachrichten englisch, im Imperativ, mit Co-Authored-By-Zeile.

## Prüf-Schwerpunkte

1. `npm run build` lief lokal noch nie: Der Build scheitert in der CI, obwohl `npm run check` grün ist → Schritt 1
   baut zuerst lokal.
2. Die neue YAML-Datei ist nicht nach Prettier formatiert, `format:check` wird rot → Schritt 3 prüft lokal mit
   `npm run check`.
3. `package-lock.json` vom Mac fehlen Linux-Pakete (z. B. native Tailwind/lightningcss), `npm ci` scheitert auf
   Ubuntu → zeigt sich im ersten CI-Lauf (Schritt 5).
4. Die CI meldet Grün, obwohl sie gar nicht prüft → Probedatei macht sie rot (Schritt 5).
5. Die Probedatei landet versehentlich in `main` → Schritt 6 löscht sie, `git ls-files app/ci-probe.ts` ist leer.

## Dateien

- Neu: `.github/workflows/ci.yml`: der Workflow, Job `check`
- Ändern: `package.json`: Feld `engines`
- Neu: `docs/tools/GitHub Actions - Einrichtung.md`: wie die CI hier eingerichtet ist, Befehle, Fehler
- Ändern: `docs/tools/Tools Übersicht.md`: Zeile für GitHub Actions
- Vorübergehend: `app/ci-probe.ts`: absichtlich falsch formatiert, wird wieder gelöscht

### Aufgabe 1: CI-Workflow mit Beweis

**Schnittstellen:**
- Nutzt: npm-Skripte `check` und `build` aus `package.json`
- Liefert: Check `CI / check` an jedem PR, auf den sich alle späteren PRs verlassen

- [x] **Schritt 1: Lokal bauen**

`npm run build`
Erwartet: Exit-Code 0, Ausgabe endet mit der Routentabelle (`○ /`). Scheitert der Build, zuerst das beheben.

- [x] **Schritt 2: `engines` und Workflow anlegen**

`package.json`: `"engines": { "node": "24.x" }` nach `"private"`.
`.github/workflows/ci.yml`: Aufbau wie musik-app (Kopfkommentar mit Verweis auf
`docs/tools/GitHub Actions - Einrichtung.md`; `checkout@v7`; `setup-node@v7` mit `node-version-file: package.json`
und `cache: npm`; Schritte „Abhängigkeiten installieren“ `npm ci`, „Prüfungen (lint, format:check, typecheck,
test)“ `npm run check`, „Produktionsfassung bauen“ `npm run build`).

- [x] **Schritt 3: Lokal prüfen**

`npm run check`
Erwartet: Exit-Code 0, `Tests 1 passed`.

- [x] **Schritt 4: Probedatei anlegen, committen, PR öffnen**

`app/ci-probe.ts` mit `export const probe   =   1` (falsch formatiert).

```bash
git add package.json .github/workflows/ci.yml app/ci-probe.ts docs/plaene/2026-10-25-ci.md
git commit -m "Add CI workflow with failing format probe"
git push -u origin ci/github-actions
gh pr create --title "Add CI with GitHub Actions" --body "…"
```

- [x] **Schritt 5: CI muss rot werden**

`gh pr checks --watch`
Erwartet: `check` fail. `gh run view <id> --log-failed` zeigt `[warn] app/ci-probe.ts` und
`Code style issues found` im Schritt „Prüfungen“. Scheitert stattdessen `npm ci` (Prüf-Schwerpunkt 3), das zuerst
beheben.

- [x] **Schritt 6: Probedatei löschen, CI muss grün werden**

```bash
git rm app/ci-probe.ts
git commit -m "Remove CI probe file"
git push
gh pr checks --watch
```

Erwartet: `check` pass. `git ls-files app/ci-probe.ts` gibt nichts aus.

- [x] **Schritt 7: Doku und committen**

`docs/tools/GitHub Actions - Einrichtung.md` nach dem Muster von musik-app: was die CI prüft, Einrichtung mit
Datum und PR-Nummer, Regel „vor jedem Merge `gh pr checks <nr>`“, Befehle, Fehler aus Schritt 5 (und jeder
weitere echte Fehler mit Ursache und Lösung), Dauer eines Laufs aus `gh run list`.
`Tools Übersicht.md`: Zeile `[[GitHub Actions]]`, Seit 2026-10-25, „prüft jeden PR mit `npm run check` und Build“,
plus Link auf die Einrichtungsnotiz mit Pfad
(`[[projects/tages-dashboard/docs/tools/GitHub Actions - Einrichtung|…]]`, den Namen hat musik-app auch).

```bash
npm run check
git add "docs/tools/GitHub Actions - Einrichtung.md" "docs/tools/Tools Übersicht.md"
git commit -m "Document CI setup"
git push && gh pr checks --watch
```

Erwartet: `check` pass.
