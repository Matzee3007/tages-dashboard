# Plan: PWA

**Ziel:** Das Dashboard lässt sich auf iPhone und iPad zum Home-Bildschirm und auf dem Mac zum Dock hinzufügen, startet
mit eigenem Symbol und dem Namen „Heute“ im eigenen Fenster, und die Anmeldung bleibt erhalten.

**Vorgehen:** Next.js erzeugt das Manifest (Steckbrief der App für den Browser) aus `app/manifest.ts`, die Symbole liegen
als Dateien in `public/icons/`. Beides muss ohne Anmeldung erreichbar sein, weil der Browser es ohne Cookies abruft. Darum
kommen zwei enge Ausnahmen in den Proxy. Am Ende zählt der Test auf den echten Geräten. Der geht erst nach dem Merge, weil
die Vorschauen hinter dem Vercel-Login liegen.

**Technik:** Next.js 16 (`app/manifest.ts`, `metadata`, `viewport`), `sips` von macOS für die PNG-Dateien, Vitest.

**Anforderung:** [[projects/tages-dashboard/docs/Projektvision|Projektvision]], Fahrplan Phase 1, Schritt 3, und
[[projects/tages-dashboard/docs/Nächste Session|Nächste Session]].

## Feste Vorgaben

- Branch `feature/pwa`, ein PR für Plan, Code und Doku. Vor dem Merge `/code-review`.
- Langer Name „Tages-Dashboard“, kurzer Name „Heute“, Start-Adresse `/`, Anzeige `standalone`.
- Farben aus dem [Entwurf](https://claude.ai/artifact/VeWhiFgrVYtqnrivy3hFKt): Orange `#FF8A3D`, dunkler Grund `#0E1013`.
- Symbole: PNG in 180, 192 und 512 px, ohne runde Ecken und ohne Transparenz (die Ecken rundet das Gerät selbst).
- Das SVG wird vom Entwickler freigegeben, bevor die PNG-Dateien entstehen.
- Der Proxy lässt ohne Anmeldung nur `/manifest.webmanifest` und `/icons/…` durch, alles andere bleibt geschützt
  ([[projects/tages-dashboard/docs/adr/0002-login-nur-auf-dem-server|ADR 0002]]).
- Keine neue Abhängigkeit, kein Service Worker (Hintergrund-Skript für Offline und Push): Offline-Daten und Push sind nicht
  geplant, und zum Installieren braucht es ihn laut Next.js-Anleitung nicht.
- Vor jedem Commit `npm run check`. Commit-Nachrichten englisch, im Imperativ, mit Co-Authored-By-Zeile.

## Prüf-Schwerpunkte

1. Abgemeldetes Gerät ruft Manifest oder Symbol ab → Datei kommt an, keine Weiterleitung auf `/login`, sonst gäbe es ein
   Standardsymbol → Aufgabe 2, Test „lässt aus“, und Aufgabe 4, Schritt 6.
2. Ähnlich benannter Pfad wie `/icons-alt` oder `/manifest.webmanifest/x` → bleibt geschützt → Aufgabe 2, Test „prüft“.
3. Manifest nennt eine Symboldatei, die fehlt oder eine falsche Größe hat → Test schlägt fehl, nicht erst das Gerät zeigt
   es → Aufgabe 3, Test 2.
4. Installierte App abgemeldet öffnen und anmelden → Login und Startseite bleiben im App-Fenster, kein Sprung nach
   Safari → Aufgabe 6, Prüfung 2.
5. App ganz schließen und neu öffnen, auch am nächsten Tag → weiterhin angemeldet → Aufgabe 6, Prüfung 3.

## Bewusst nicht in diesem Schritt

- Dunkles Aussehen der Seiten und die Schriften aus dem Entwurf: kommen mit dem Kachel-Gerüst. Bis dahin kann die Seite im
  hellen Modus des Geräts weiß sein.
- Startbilder (`startupImage`), eigener Installieren-Knopf.

test("nennt Namen, Start und Farben", () => {

    name: "Tages-Dashboard",
    short_name: "Heute",
    start_url: "/",
    display: "standalone",
    background_color: "#0E1013",
    theme_color: "#0E1013",
  });
});

// Die Breite steht in jeder PNG-Datei ab Byte 16.
test("jedes Symbol gibt es in der genannten Größe", () => {
  const symbole = manifest().icons!;
  expect(symbole.map((s) => s.sizes)).toEqual(["192x192", "512x512"]);
  for (const symbol of symbole) {
    const datei = readFileSync(join(process.cwd(), "public", symbol.src));
    expect(`${datei.readUInt32BE(16)}x${datei.readUInt32BE(20)}`).toBe(symbol.sizes);
  }
});
