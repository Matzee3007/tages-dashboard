# Plan: Online auf Vercel

**Ziel:** Die App läuft unter einer `*.vercel.app`-Adresse. Jeder Merge auf `main` geht live, jeder PR bekommt
eine geschützte Vorschau.

**Vorgehen:** Das Repo wird über die Git-Integration von Vercel verbunden, von Hand im Vercel-Dashboard. Ein
Assistent-Skript (Skill `assistent-bauen`) führt durch die Klicks. Code ändert sich nicht. Next.js wird von Vercel
erkannt, Node kommt aus `engines` in `package.json`. Den Beweis liefern der PR dieses Plans selbst (Vorschau) und
der Merge (Produktion), geprüft mit `curl` und `gh`.

**Technik:** Vercel (Tarif Hobby, Git-Integration, Deployment Protection), `gh`, `/usr/bin/curl`.

**Anforderung:** [[projects/tages-dashboard/docs/Projektvision|Projektvision]], Fahrplan Phase 1, Schritt 1, und
die Befragung vom 2026-10-25.

## Feste Vorgaben

- Branch `deploy/vercel`, ein PR für Plan und Doku.
- Keine Vercel-CLI, keine `vercel.json`, keine Umgebungsvariablen (die kommen erst mit Schritt 2, Login).
- Vercel-Projektname `tages-dashboard`, Produktions-Branch `main`, Adresse `*.vercel.app`, keine eigene Domain.
- Die Vercel-App auf GitHub bekommt nur Zugriff auf das Repo `tages-dashboard` („Only select repositories“).
- Vorschauen geschützt mit Deployment Protection „Vercel Authentication“, Umfang „Standard Protection“
  (alles außer der Produktionsadresse).
- Konten bei Vercel und Supabase gibt es schon.
- Assistent-Skript liegt im Scratchpad, nicht im Repo.
- HTTP-Abfragen mit `/usr/bin/curl` (Regel der globalen `CLAUDE.md`).
- Vor jedem Commit `npm run check`. Commit-Nachrichten englisch, im Imperativ, mit Co-Authored-By-Zeile.
- Gemergt wird erst, wenn `gh pr checks <nr>` für CI und Vercel grün meldet.

## Prüf-Schwerpunkte

1. Der Build scheitert bei Vercel, obwohl die CI grün ist (andere Node-Version, `cacheComponents` in
   `next.config.ts`) → Aufgabe 2, Schritt 2: der Vercel-Check im PR muss `pass` sein.
2. Die Vorschau ist ohne Anmeldung öffentlich → Aufgabe 2, Schritt 3: `curl` auf die Vorschau-Adresse darf nicht 200
   liefern.
3. Ein PR-Branch geht statt `main` in Produktion → Aufgabe 3, Schritt 2: das neueste Deployment mit Umgebung
   `Production` gehört zum Merge-Commit auf `main`.
4. Die Produktionsadresse ist versehentlich auch geschützt → Aufgabe 1, Schritt 3 und Aufgabe 3, Schritt 3: `curl`
   liefert 200 und den Seitentitel.
5. Die Vercel-App bekommt Zugriff auf alle Repos → Aufgabe 1, Schritt 1 (Assistent fragt die Auswahl ab).

### Aufgabe 1: Repo mit Vercel verbinden

**Schnittstellen:**
- Nutzt: npm-Skript `build` aus `package.json`, `engines.node` = `24.x`
- Liefert: Produktionsadresse `https://<name>.vercel.app` und den Check `Vercel` an jedem PR, auf den sich
  Schritt 2 (Login) verlässt

- [x] **Schritt 1: Assistent schreiben und laufen lassen**

Mit `assistent-bauen`, Stufen in dieser Reihenfolge. Die genauen Klickwege vorher in der Vercel-Doku nachlesen,
nicht aus dem Gedächtnis:

1. `https://vercel.com/new` öffnen, „Import Git Repository“, die GitHub-App von Vercel nur für `tages-dashboard`
   freigeben.
2. Repo importieren: Projektname `tages-dashboard`, Framework „Next.js“ (erkannt), keine Umgebungsvariablen,
   „Deploy“.
3. Produktionsadresse abfragen (`frage`, öffentlich, nirgends hineingeschrieben, nur ausgeben).
4. Settings → Deployment Protection: „Vercel Authentication“ an, „Standard Protection“ bestätigen.
5. Settings → Git: Production Branch ist `main`.

Erwartet: Zusammenfassung des Assistenten mit der Produktionsadresse.

- [x] **Schritt 2: Ersten Build ansehen**

```bash
gh api repos/Matzee3007/tages-dashboard/deployments --jq '.[0] | {environment, ref}'
```

Erwartet: `{"environment":"Production","ref":"main"}` (der Import baut sofort `main`).

Ergebnis 2026-10-26: `null`. Der Build beim Import erscheint nicht als Deployment bei GitHub (kein Push).
Die Prüfung, dass `main` in Produktion geht, übernimmt Aufgabe 3, Schritt 2.

- [x] **Schritt 3: Produktion antwortet**

```bash
/usr/bin/curl -s -o /dev/null -w '%{http_code}\n' 'https://<name>.vercel.app'
/usr/bin/curl -s 'https://<name>.vercel.app' | grep -o '<h1[^>]*>Tages-Dashboard</h1>'
```

Erwartet: `200` und die Überschrift `Tages-Dashboard`.

Ergebnis 2026-10-26: `200` und `<h1 …>Tages-Dashboard</h1>` unter `https://tages-dashboard-iota.vercel.app`.

### Aufgabe 2: Geschützte Vorschau am PR

**Schnittstellen:**
- Nutzt: Vercel-Projekt aus Aufgabe 1
- Liefert: Vorschau-Adresse je PR, nur mit Vercel-Anmeldung erreichbar

- [x] **Schritt 1: Doku schreiben und PR öffnen**

`docs/tools/Vercel.md` im Aufbau der anderen Tool-Notizen (Was ist das, wofür nutzen wir es, Begriffe: Deployment,
Produktion, Vorschau, Deployment Protection; Einrichtung wie in Aufgabe 1; Befehle aus diesem Plan; Fehler).
Zeile in `Tools Übersicht.md` (`| [[projects/tages-dashboard/docs/tools/Vercel\|Vercel]] | 2026-10-26 | bringt die
App ins Netz, Vorschau je PR |`). In `README.md` die Live-Adresse unter „Loslegen“ und den Codeblock um
`npm ci`/`npm run dev` reparieren.

```bash
npm run check
git add docs/plaene/2026-10-26-vercel.md docs/tools/Vercel.md "docs/tools/Tools Übersicht.md" README.md
git commit -m "Deploy to Vercel and document setup"
git push -u origin deploy/vercel
gh pr create
```

- [x] **Schritt 2: Vercel baut den PR**

`gh pr checks <nr> --watch`
Erwartet: `check` (CI) und `Vercel` beide `pass`.

Ergebnis 2026-10-26 (PR #9): `check`, `Vercel` und `Vercel Preview Comments` alle `pass`.

- [x] **Schritt 3: Vorschau ist geschützt**

Vorschau-Adresse aus dem Kommentar des Vercel-Bots im PR.

```bash
gh pr view <nr> --json comments --jq '.comments[].body' | grep -oE 'https://[a-zA-Z0-9.-]+\.vercel\.app' | sort -u
/usr/bin/curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' '<vorschau-adresse>'
```

Erwartet: `401` (oder eine Weiterleitung auf `vercel.com`), nicht `200`. Im Browser mit Vercel-Anmeldung zeigt
dieselbe Adresse die Seite.

Ergebnis 2026-10-26: `302` mit Weiterleitung auf `https://vercel.com/sso-api?…`. `gh pr view --comments` lässt sich
nicht mit `--json` kombinieren, deshalb `--json comments`.

### Aufgabe 3: Merge geht live

**Schnittstellen:**
- Nutzt: PR aus Aufgabe 2
- Liefert: Ablauf „Merge auf `main` = live“, auf den sich alle weiteren Schritte verlassen

- [ ] **Schritt 1: Mergen**

```bash
gh pr view <nr> --json mergeable --jq .mergeable   # erwartet MERGEABLE
gh pr merge <nr> --merge --delete-branch
```

- [ ] **Schritt 2: Produktion kommt vom Merge-Commit**

```bash
git switch main && git pull
gh api "repos/Matzee3007/tages-dashboard/commits/$(git rev-parse HEAD)/check-runs" \
  --jq '.check_runs[] | select(.name=="Vercel") | {conclusion, output: .output.title}'
```

Erwartet: ein Check `Vercel` am Merge-Commit auf `main` mit `conclusion` = `success`. Vercel legt in diesem Repo
keine GitHub-Deployments an (`gh api …/deployments` liefert `0`, geprüft an PR #9), deshalb der Check statt der
Deployments-Liste.

- [ ] **Schritt 3: Produktion antwortet weiterhin**

Befehle aus Aufgabe 1, Schritt 3. Erwartet: `200` und die Überschrift.
